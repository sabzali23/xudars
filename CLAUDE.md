# CLAUDE.md

Это файл контекста проекта для Claude Code. Он описывает продукт, модель данных и правила, которых нужно придерживаться при разработке. Актуализируйте этот файл по мере уточнения требований (особенно раздел «Открытые вопросы»).

## 1. Суть проекта

Веб-платформа (сайт/приложение), которая помогает родителям готовить детей к конкурсному поступлению в школу в Хороге.

Вместо общего курса или разрозненных видео платформа даёт по каждой теме экзамена чёткий цикл:

**диагностика → материал (видео + пошаговое объяснение) → повторная диагностика → понятный результат «было/стало» → рекомендация, что делать дальше.**

Ключевая ценность: дешевле и доступнее репетитора, при этом даёт конкретику (что именно учить) и снимает с родителя необходимость самому быть педагогом-методистом.

По структуре сайт ориентируется на формат онлайн-школ вроде «Парта», но вместо подготовки к ЕГЭ — это каталог курсов для подготовки к поступлению в школу: общая тема сайта «подготовка к поступлению в школу», внутри — отдельные курсы по предметам (первый и единственный в v1 — курс «Математика», остальные показаны как «скоро»).

## 2. Пользователь и проблема

**Пользователь:** родитель ребёнка, который готовится к конкурсному поступлению в школу в Хороге. Основной действующий пользователь интерфейса — родитель; ребёнок — тот, кто проходит материал и тесты, часто вместе с родителем.

**Возраст ребёнка.** Первый модуль курса («Простая арифметика») рассчитан на ребёнка 6–7 лет, поступающего в 1 класс: счёт до 10, сложение и вычитание в пределах 10, в конце — числа до 20 и деление поровну; счёт на пальцах и предметах в этом возрасте допустим. Остальные демо-темы (дроби, проценты, задачи на движение) написаны на уровень 3–4 класса — их нужно либо пересмотреть под возраст поступающих, либо явно отнести к другому курсу.

**Проблема состоит из двух частей:**

1. Родители и дети не знают конкретно, что будет на экзамене и над чем именно работать — информация непрозрачна, распространяется в основном через репетиторов или сарафанное радио.
2. Даже когда тема понятна, у родителей нет методики, как эффективно заниматься с ребёнком дома — они не педагоги и не умеют объяснять/выстраивать процесс.

**Текущая альтернатива:** платные репетиторы — не всем доступны по цене и не всегда физически доступны в регионе.

## 3. Модель данных

| Сущность | Модель Django | Поля | Связи |
|---|---|---|---|
| Пользователь (родитель) | `accounts.User` | id, phone (логин, формат +992…), name, telegram (необяз.), пароль | 1 — много «Детей» |
| Ребёнок (профиль) | `children.Child` | id, name, grade (класс 1–11), target_school, created_at | принадлежит Пользователю (ForeignKey: детей может быть несколько) |
| Раздел (предмет) | `curriculum.Section` | id, slug, title, description (текст карточки курса), order | 1 — много «Тема» |
| Тема | `curriculum.Topic` | id, section_id, slug, title, order | принадлежит Разделу |
| Материал | `curriculum.Material` | id, topic_id, video_url (необяз.), summary_md (обязателен), summary_html, parent_guide_md («как провести занятие», обязателен), parent_guide_html | принадлежит Теме (OneToOne) |
| Задание (вопрос) | `curriculum.Question` | id, topic_id, pool (entry/final), order, text, options (JSON), correct_index, explanation | принадлежит Теме |
| Попытка теста | `learning.TestAttempt` | id, child_id, topic_id, kind (entry/final), question_ids (JSON), answers (JSON), score (%), started_at, finished_at | связывает Ребёнка и Тему |
| Прогресс по теме | `learning.TopicProgress` | child_id, topic_id, status (not_started/in_progress/passed/needs_repeat), stage (entry_test/material/final_test/done), entry_score, last_score, updated_at | связывает Ребёнка и Тему |
| Заявка на консультацию | `leads.ConsultationRequest` | id, name, grade, phone (+992…), created_at, handled_at | ни с кем не связана: заявка оставляется до регистрации |

Служебные поля: `stage` хранит текущий шаг цикла (порядок шагов и «на чём остановились»), `explanation` используется в разборе ошибок, `question_ids`/`answers` сохраняются после каждого ответа, чтобы прерванный тест продолжался с того же задания.

**Уточнить:** точный список разделов/предметов и тем — должен соответствовать реальной программе вступительного экзамена конкретной школы. Сейчас в `content/math` четыре демо-темы (`"draft": true`), первая — «Простая арифметика»; в `content/english` четыре темы — «Английский алфавит», «Числа от 1 до 10», «Животные и слова по картинкам», «Что делают сейчас: is/are и окончание -ing». Последние две написаны **по реальному листу заданий с экзамена**, который дал владелец проекта (задания: выбрать слово из скобок в предложении, вставить пропущенные буквы в слове, узнать слово по картинке, подписать картинку). Это первый реальный материал по программе — остальные темы пока остаются догадкой, поэтому раздел всё ещё `"draft": true`. В `content/logic` три темы — «Цепочка вычислений», «Порядок и закономерности», «Что лишнее и что подходит»; они тоже написаны по реальному листу заданий (цепочка чисел со стрелками, расстановка картинок по порядку, пропущенный день недели, продолжение ряда, «кто где живёт», «что лишнее»). Курсов теперь три, и `COMING_SOON_COURSES` пуст — тесты, которые проверяют вывод карточек «Скоро», задают этот список сами через `override_settings`.

## 4. Сценарии

**Сценарий 1 — первый вход.**
Родитель заходит впервые → создаёт профиль ребёнка (имя, класс, целевая школа) → попадает на главный экран.

**Сценарий 2 — основной цикл (открытие → закрытие).**
Главный экран (рекомендованная тема) → входной тест по теме → материал (видео + конспект) → итоговый тест → экран результата (было/стало, разбор ошибок) → рекомендация следующего шага → возврат на главный экран или выход. Прогресс сохраняется автоматически при каждом действии.

**Сценарий 3 — возврат в приложение.**
Родитель/ребёнок открывает платформу повторно → система сразу показывает, на чём остановились, и предлагает продолжить с рекомендованной темы, а не с начала списка.

**Сценарий 4 — просмотр общего прогресса.**
Родитель открывает профиль ребёнка → видит прогресс по всем пройденным темам/разделам и карту слабых мест (в каких темах результат ниже). На экране прогресса по каждому курсу есть диаграмма: кольцо «сколько тем пройдено» и полосы «было → стало» по каждой теме (всё рисуется на сервере в SVG, без JS).

## 5. Экраны

1. **Экран входа/профиля** — при первом входе создание профиля ребёнка (имя, класс, целевая школа); дальше это страница профиля: данные родителя (имя, телефон, Telegram, дата регистрации) и карточка на каждого ребёнка с его данными и прогрессом по курсам. Детей может быть несколько: есть кнопка «Добавить ребёнка», правка данных и переключение «Заниматься с …». Тот, с кем занимаются сейчас, выделен рамкой. Выбор хранится в сессии (`children/selection.py`), и экраны занятий получают ребёнка через `child_required` — сами они о выборе ничего не знают. Прогресс, попытки и рекомендации всегда привязаны к конкретному ребёнку и не смешиваются.
2. **Главный экран / каталог курсов** — оформлен как каталог курсов по предметам (по аналогии с витриной курсов онлайн-школ): карточка «Математика» — активный курс с индикатором прогресса и кнопкой «Продолжить»/«Начать»; карточки остальных предметов (напр. Английский, Логика) — показаны как «Скоро», неактивны в v1. Внутри открытого курса — рекомендованная следующая тема как основное действие. *(Реализация: `/` — для гостя лендинг `templates/landing.html`, для родителя каталог `learning/catalog.html`; курс — `/course/<slug>/`. Гостю без входа видны каталог курсов и программа курса — список модулей (`learning/course_public.html`), но содержимое модуля закрыто: ссылка модуля ведёт на `/login/?next=/topic/<slug>/`, и после входа родитель попадает сразу в этот модуль. Предметы «Скоро» — `settings.COMING_SOON_COURSES`, название сайта и контакт — `SITE_NAME`/`SITE_CONTACT`. Исходный макет — `design/landing/`.)*
3. **Экран входного теста** — по одному заданию на экран, прогресс «задание N из M».
4. **Экран материала** — видео + текстовый конспект (текст обязателен как запасной вариант при слабом интернете).
5. **Экран итогового теста** — та же механика, что и входной тест, с другими (равнозначными по сложности) заданиями.
6. **Экран результата** — сравнение баллов до/после, разбор конкретных ошибок.
7. **Экран рекомендации** — следующий шаг: новая тема или повтор текущей с дополнительными заданиями.

## 6. Правила и ограничения

- Материал по теме открывается только после прохождения входного теста по этой теме (последовательность нельзя пропустить).
- Итоговый тест использует другой набор заданий той же темы и сложности, а не те же вопросы, что во входном тесте.
- Рекомендация следующей темы формируется по простому правилу: в приоритете темы с низким баллом или незавершённые темы (без сложных ИИ-рекомендаций на первом этапе).
- Каждый материал обязан иметь текстовый конспект, а не только видео — из-за нестабильного и дорогого интернета в регионе видео не должно быть единственным источником объяснения.
- Разделы добавляются только после подтверждения, что они входят в реальную программу конкретного вступительного экзамена. Сейчас их два: «Математика» и «Английский язык» (последний добавлен по прямой просьбе владельца, тема «Английский алфавит» для шестилетних). Оба помечены `"draft": true` — список тем нужно сверить с реальным экзаменом.
- Минимальный сбор персональных данных о ребёнке (только то, что нужно для профиля и подбора материала).
- На начальном этапе роль «ведущего» занятие выполняет родитель — материал и пошаговое объяснение должны быть понятны и применимы именно родителем, а не рассчитаны только на самостоятельный просмотр ребёнком. В коде: у каждого материала обязательно руководство «как провести занятие» (`guide.md` → `Material.parent_guide_md`), оно показывается первым на экране материала; подсказки для родителя есть на экранах тестов и разбора ошибок.

## 7. Не входит в первую версию (v1 scope)

- Новые разделы без проверки, что они есть в реальном экзамене (курс «Английский язык» добавлен по отдельной просьбе и ждёт такой проверки; «Логика» и прочие остаются в списке «Скоро» — `settings.COMING_SOON_COURSES`).
- Оплата/монетизация.
- Геймификация (баллы, значки, стрики).
- Админ-панель для самостоятельного добавления контента (в v1 контент добавляется вручную/напрямую).
- Социальные функции (рейтинги, сравнение с другими детьми, публичные профили).
- Нативное мобильное приложение (v1 — только сайт, адаптированный под мобильные экраны).
- Уведомления/напоминания о занятиях.
- Офлайн-режим/скачивание материалов.
- Продвинутая аналитика для родителя за пределами базового экрана результата и карты слабых мест.
- Живая проверка/обратная связь от преподавателя — в первой версии роль наставника выполняет родитель с помощью материалов сайта, экспертная проверка задач не предусмотрена.

## 8. Открытые вопросы (уточнить до/во время разработки)

- Точный список тем по математике для конкретной целевой школы в Хороге (программа вступительного экзамена). Сейчас загружены демо-темы.
- Формат хранения видео (self-hosted vs. YouTube/сторонний сервис) с учётом слабого/дорогого интернета в регионе. Сейчас в материале хранится только необязательная ссылка, на экране — кнопка «Смотреть видео» (без встроенного плеера).
- Хостинг и продакшен-БД (сейчас SQLite; переход на PostgreSQL не требует изменений кода).

**Решено:**

- Стек: Python 3.12 + Django 5, серверные шаблоны и HTML-формы без JS-фреймворков, собственный лёгкий CSS, WhiteNoise для статики.
- Вход родителя: телефон + пароль (номер нормализуется к виду +992…, см. `accounts/phone.py`).
- Контент: JSON + Markdown в `content/`, загрузка командой `manage.py load_content` с проверками (формат — в README.md).
- Порог прохождения темы — 80% (`settings.PASS_THRESHOLD`), размер теста — 5 заданий (`settings.TEST_SIZE`).
- Название и фирменный стиль: **XuDars** (`settings.SITE_NAME`). Логотип — зелёная сова на раскрытой книге. И в шапке, и в футере лендинга используется логотип целиком, без обрезки до знака — `static/img/logo-full.png` (700×332, 194 КБ; из исходника убраны только пустые белые поля — границы рисунка вычислены сканом непустых пикселей, — а фон сделан прозрачным). Прозрачность здесь обязательна: в JPEG белый фон сохранялся как `#fdfdfd` и на белой шапке логотип смотрелся заплаткой с видимой рамкой. В шапке логотип выведен по высоте: 95px на телефоне и 143px на широком экране, высота самой шапки подстроена под него (109px / 164px). В футере лендинга логотип крупнее — 280px по ширине. Размеры задаются только высотой (ширина считается по пропорциям файла), и при их изменении нужно двигать и `min-height` шапки, иначе логотип упрётся в края. Название рядом с логотипом не дублируется текстом, потому что оно есть в самом логотипе; иконка вкладки — `static/img/favicon.png`. Исходник (1,25 МБ) лежит вне проекта и на сайте не используется — он слишком тяжёл для местного интернета. Палитра снята пиксельно с логотипа: `--accent: #0c6c3c` (самая частая зелень совы), `--accent-dark: #00543c`, `--leaf: #54a848` (светлый лист, заливка полос прогресса); фон и границы с зелёным оттенком; `--high` остаётся за статусом «тема пройдена». Ссылка на CSS в `base.html` идёт с `?v=N` — при правке стилей номер нужно увеличивать, иначе браузер отдаёт старый файл из кеша.

## Структура кода

- `accounts/` — родитель, регистрация и вход по телефону.
- `children/` — профили детей (их может быть несколько), выбор активного ребёнка в `selection.py`, декоратор `child_required`.
- `curriculum/` — разделы, темы, материалы, задания; `content_loader.py` и команда `load_content`.
- `learning/services/progress.py` — порядок шагов цикла и переходы статусов (все проверки доступа — здесь).
- `learning/services/quiz.py` — выбор заданий (итоговый тест только из пула final, при повторе — сначала нерешённые), ответы, балл, разбор ошибок.
- `learning/services/recommendation.py` — детерминированное правило рекомендации: незавершённая тема → «нужно повторить» с наименьшим баллом → первая не начатая → самая слабая пройденная.
- `leads/` — заявки на консультацию с лендинга (форма «Хочу консультацию»); читаются командой `manage.py leads`, потому что админ-панели в v1 нет.
- Автотесты: `manage.py test` (в `learning/tests.py` проверяются инварианты раздела 6).

## 9. Указания для разработки (Claude Code)

- При работе над кодом соблюдать правила из раздела 6 как инварианты (например: не давать доступ к материалу без пройденного входного теста).
- Не добавлять функциональность из раздела 7 (не входит в v1), пока это явно не запрошено.
- При любых изменениях модели данных (раздел 3) — обновлять этот файл.
- Предпочитать простые решения: правило рекомендаций (раздел 6) должно оставаться детерминированным и понятным, без ML/AI-логики на этом этапе.
- Учитывать нестабильный интернет в регионе (Хорог, ГБАО): текстовый конспект — не опция, а обязательное требование к каждому материалу; UI должен нормально работать на слабом соединении и мобильных экранах.

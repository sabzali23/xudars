# Подготовка к вступительному экзамену (Хорог)

Сайт для родителей: по каждой теме экзамена ребёнок проходит цикл
**входной тест → материал (конспект + видео) → итоговый тест → было/стало и разбор ошибок → рекомендация**.

Стек: Python 3.12, Django 5, серверные шаблоны без JS-фреймворков, SQLite. Подробности продукта — в [CLAUDE.md](CLAUDE.md).

## Запуск (Windows PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py load_content
.\.venv\Scripts\python.exe manage.py runserver
```

Откройте http://127.0.0.1:8000/ и зарегистрируйтесь.

Автотесты:

```powershell
.\.venv\Scripts\python.exe manage.py test
```

## Контент

Админ-панели в v1 нет. Контент хранится в папке `content/` и загружается командой `manage.py load_content`.
Команду можно запускать повторно: темы обновляются по имени папки, прогресс детей сохраняется.

```
content/
  math/                         ← раздел (имя папки = slug)
    section.json                {"title": "Математика", "order": 1, "draft": true}
    topics/
      fractions/                ← тема (имя папки = slug: латиница, цифры, дефисы)
        topic.json
        summary.md              ← конспект, обязателен
        guide.md                ← «как провести занятие» для родителя, обязателен
```

`guide.md` — сценарий занятия для родителя: в v1 занятие ведёт родитель, преподавателя нет. Рекомендуемая структура:
подготовка → шаги объяснения с вопросами к ребёнку и ответами → проверка понимания с ответами →
что делать при типичных ошибках → напоминание, что итоговый тест ребёнок решает без подсказок.

`topic.json`:

```json
{
  "title": "Обыкновенные дроби",
  "order": 1,
  "video_url": "",
  "questions": {
    "entry": [
      {"text": "Вычислите: 1/4 + 2/4.", "options": ["3/8", "3/4"], "correct": 1, "explanation": "..."}
    ],
    "final": []
  }
}
```

- `correct` — номер правильного варианта, считая с 0.
- В `entry` и `final` должно быть не меньше заданий, чем `TEST_SIZE` (5). Дополнительные задания в `final` используются при повторе темы.
- Одно и то же задание не может быть и во входном, и в итоговом тесте.
- Задания сопоставляются по порядку в списке. После запуска **не переставляйте и не удаляйте задания из середины списка** — новые добавляйте в конец, иначе старые результаты покажут другие вопросы.
- `summary.md` рендерится как Markdown. Контент считается доверенным (попадает в репозиторий через ревью).

Если в контенте ошибка, команда выводит путь к файлу и ничего не записывает в базу.

Текущие темы — **демо** (`"draft": true`). Их нужно заменить реальной программой вступительного экзамена.

## Заявки на консультацию

Внизу лендинга есть форма «Хочу консультацию» (имя, класс, телефон). Заявки сохраняются в базу;
админ-панели в v1 нет, поэтому смотреть их нужно командой:

```powershell
.\.venv\Scripts\python.exe manage.py leads              # новые заявки
.\.venv\Scripts\python.exe manage.py leads --all        # вместе с обработанными
.\.venv\Scripts\python.exe manage.py leads --handled 3  # отметить заявку №3 обработанной
```

Телефон нормализуется так же, как при регистрации: 9 цифр считаются таджикским номером и приводятся к виду `+992…`.
В форме собираются персональные данные, поэтому перед публичным запуском нужна страница с политикой обработки
персональных данных — сейчас под формой стоит только текст согласия, без ссылки.

## Размещение в интернете (Render)

Развёртывание описано в [render.yaml](render.yaml): веб-сервис и база PostgreSQL. Порядок такой:

1. Отправить проект на GitHub.
2. На [render.com](https://render.com) → **New → Blueprint** → выбрать репозиторий. Render прочитает `render.yaml`
   и сам создаст сервис и базу.
3. Дождаться первой сборки: она ставит зависимости, собирает статику, применяет миграции и загружает
   учебный контент командой `load_content`.

Что важно знать:

- **База**. Локально проект работает на SQLite, на хостинге — на PostgreSQL. Переключение происходит само:
  если задана переменная `DATABASE_URL`, используется она. Файл `db.sqlite3` в репозиторий не попадает —
  в нём личные данные родителей и детей.
- **Учебный контент** хранится в папке `content/` и заливается в базу при каждой сборке, поэтому новые темы
  появляются на сайте сразу после отправки изменений на GitHub.
- **Бесплатный тариф Render** усыпляет сайт после простоя: первый заход после паузы занимает около минуты.
  Бесплатная база выдаётся на ограниченный срок — условия стоит проверить при создании.
- `DJANGO_SECRET_KEY` Render генерирует сам, `DJANGO_DEBUG` выставлен в `0`; адрес сайта Django берёт из
  переменной `RENDER_EXTERNAL_HOSTNAME`, которую Render подставляет автоматически.

## Настройки

- `SITE_NAME` — название сайта в шапке и футере, по умолчанию `XuDars` (можно переопределить переменной окружения).
- `SITE_CONTACT` — Telegram или телефон в футере лендинга (пусто — строка не показывается).
- `COMING_SOON_COURSES` — предметы, показанные в каталоге как «Скоро».
- `STUDENT_STORIES` — истории учеников в слайдере на первом экране лендинга. Сейчас это образцы:
  имена-заглушки и рисованные картинки `static/img/students/sample-*.svg` (не фото реальных детей).
  Чтобы поставить настоящее фото, положите файл в `static/img/students/` и укажите путь относительно `static/`
  (например `"photo": "img/students/ali.jpg"`); если `photo` пустое, показывается заглушка «Здесь будет фото ученика».
  Публиковать фото, имя и результаты ребёнка можно только с согласия родителей.

- `PASS_THRESHOLD` (80) — итоговый балл в процентах, с которого тема считается пройденной.
- `TEST_SIZE` (5) — количество заданий в тесте.
- Для продакшена задайте переменные окружения `DJANGO_SECRET_KEY`, `DJANGO_DEBUG=0`, `DJANGO_ALLOWED_HOSTS` и выполните `manage.py collectstatic`.
